# Longest Increasing Subsequence

**Difficulty:** Very Hard | **Category:** Dynamic Programming | **Pattern:** Patience sorting (binary search over tails) with reconstruction

## The problem

Return the longest **strictly increasing** subsequence of an array of integers (the elements themselves, not just the length). Assume a unique answer.

```
[5, 7, -24, 12, 10, 2, 3, 12, 5, 6, 35]  ->  [-24, 2, 3, 5, 6, 35]
```

## Step 1: The O(n^2) DP

`L[i]` = length of the longest increasing subsequence **ending at i** = `1 + max(L[j])` over `j < i` with `a[j] < a[i]`. Store `prev[i]` to reconstruct. This is the same template as Max Sum Increasing Subsequence (hard 15). Always present it first.

## Step 2: The key idea for O(n log n)

For each possible length `k`, you only need to remember **the smallest possible last element** of an increasing subsequence of length `k`. A smaller tail is always at least as good: anything that can extend a bigger tail can also extend a smaller one.

Keep an array `tails` where `tails[k]` is (the index of) that smallest tail for length `k + 1`. This array is **strictly increasing**, so it can be binary searched.

For each new element `x`:

- find the first position in `tails` whose value is `>= x` (a lower bound);
- if there is none, `x` extends the longest subsequence: **append** it;
- otherwise `x` becomes a smaller tail for that length: **replace** it.

The length of `tails` at the end is the length of the LIS. (This is called patience sorting, after the card game.)

## Step 3: Reconstruction

`tails` is **not** the LIS itself: it mixes elements of different subsequences. (Example: `[3, 4, 1]` ends with tails `[1, 4]`, which is not even a subsequence, since 1 comes after 4.)

To rebuild the answer, record for each element the index that was at `tails[pos - 1]` when it was placed: its predecessor. Walk back from the last entry of `tails`.

## Step 4: The code

```dart
// Longest Increasing Subsequence (strict), returning the subsequence itself.
// Patience sorting: tails[len] = index of the smallest tail of an increasing subsequence of
// length len + 1; binary search each element's position; keep predecessor links.
// O(n log n) time, O(n) space.

List<int> longestIncreasingSubsequence(List<int> array) {
  final tails = <int>[]; // indices into array
  final prev = List<int?>.filled(array.length, null);
  for (var i = 0; i < array.length; i++) {
    // First position whose tail value is >= array[i] (strictly increasing => lower bound).
    var lo = 0, hi = tails.length;
    while (lo < hi) {
      final mid = (lo + hi) >> 1;
      if (array[tails[mid]] < array[i]) {
        lo = mid + 1;
      } else {
        hi = mid;
      }
    }
    if (lo > 0) prev[i] = tails[lo - 1];
    if (lo == tails.length) {
      tails.add(i);
    } else {
      tails[lo] = i;
    }
  }
  final seq = <int>[];
  for (int? i = tails.isEmpty ? null : tails.last; i != null; i = prev[i]) {
    seq.add(array[i]);
  }
  return seq.reversed.toList();
}
```

### Walkthrough

- `tails` holds indices, so values are read as `array[tails[mid]]`.
- The binary search finds the lower bound (first tail `>= x`), which enforces **strict** increase.
- `prev[i] = tails[lo - 1]` records the predecessor.
- Append or replace, then reconstruct from `tails.last` through `prev`.

## Complexity

| Approach | Time | Space |
|---|---|---|
| DP | O(n^2) | O(n) |
| Patience sorting | O(n log n) | O(n) |

## Common mistakes

- Returning `tails` as the answer.
- Using an upper bound (`>`) instead of a lower bound (`>=`): that computes the longest **non-decreasing** subsequence.

## What to remember

Keep the smallest tail for each length; binary search where each new element goes. Store predecessors to rebuild the actual subsequence.
