# Count Inversions

**Difficulty:** Very Hard | **Category:** Sorting | **Pattern:** Merge sort with counting

## The problem

An **inversion** is a pair of indices `i < j` with `array[i] > array[j]`: two elements in the wrong order. Return the number of inversions. It measures how far the array is from being sorted (a sorted array has 0; a reversed one has n(n-1)/2).

```
[2, 3, 3, 1, 9, 5, 6]  ->  5
the pairs: (2, 1), (3, 1), (3, 1), (9, 5), (9, 6)
```

## Step 1: Brute force

Check every pair: **O(n^2)**.

## Step 2: Divide and conquer

Split the array into a left half and a right half. Every inversion is one of:

1. both elements in the left half,
2. both in the right half,
3. **cross:** the bigger element in the left half, the smaller in the right half.

Types 1 and 2 are counted recursively. The question is how to count type 3 quickly.

## Step 3: Counting cross inversions while merging

If both halves are **sorted**, cross inversions are easy to count during the merge:

- When the next element is taken from the **right** half (`a[j]`), it is smaller than **every remaining element of the left half** (because the left half is sorted and its current front is already bigger than `a[j]`).
- All of those remaining left elements were originally before `a[j]`. So `a[j]` forms an inversion with each of them: add `mid - i` (the number of remaining left elements) at once.

And the merge produces a sorted range, which is exactly what the parent level needs. So the counting rides along with merge sort at no extra asymptotic cost.

Use `<=` when comparing: equal elements are **not** an inversion, so on ties take from the left first.

## Step 4: The code

Full source: [`count_inversions.dart`](count_inversions.dart) (run it with `dart run`).

```dart
// Count Inversions: pairs i < j with array[i] > array[j]. Merge sort, counting cross pairs
// during each merge. O(n log n) time, O(n) space. Does not mutate the input.

int countInversions(List<int> array) {
  int sortAndCount(List<int> a, int start, int end) {
    if (end - start <= 1) return 0;
    final mid = (start + end) ~/ 2;
    var count = sortAndCount(a, start, mid) + sortAndCount(a, mid, end);
    final merged = <int>[];
    var i = start, j = mid;
    while (i < mid && j < end) {
      if (a[i] <= a[j]) {
        merged.add(a[i++]);
      } else {
        count += mid - i; // a[j] is smaller than every remaining left element
        merged.add(a[j++]);
      }
    }
    merged
      ..addAll(a.sublist(i, mid))
      ..addAll(a.sublist(j, end));
    a.setRange(start, end, merged);
    return count;
  }

  return sortAndCount([...array], 0, array.length);
}
```

### Walkthrough

- `sortAndCount(a, start, end)` sorts `a[start..end)` and returns its inversion count.
- The count is the two recursive counts plus the cross inversions found while merging.
- `count += mid - i;` is the key line.
- The input is copied first (`[...array]`), so the caller's array is not reordered.

## Complexity

- **Time: O(n log n)**.
- **Space: O(n)**.

## Common mistakes

- Using `<` in the comparison (counts equal pairs as inversions).
- Adding 1 instead of `mid - i` (misses most cross inversions).
- Counting without sorting the halves (the "all remaining left elements are bigger" argument needs sorted halves).

## Follow-ups

1. **Right Smaller Than (very hard 06):** the per-element version of the same count.
2. **Reverse Pairs (LeetCode #493):** count `i < j` with `a[i] > 2 * a[j]`; count with a separate pointer pass before each merge, because the merge order and the counting condition differ.
3. **Kendall tau distance:** the number of inversions between two rankings measures how similar they are (used in ranking evaluation).
4. **Fenwick tree alternative:** scan from the right, counting how many seen values are smaller than the current one: also O(n log n).

## What to remember

Divide and conquer counting: count inside each half recursively, and count cross pairs during the merge, where sortedness lets you add `mid - i` at once.
