# Palindrome Partitioning Min Cuts

**Difficulty:** Very Hard | **Category:** Dynamic Programming | **Pattern:** Palindrome detection + prefix DP

## The problem

Return the minimum number of **cuts** needed to split a string into pieces that are all palindromes.

```
"noonabbad"  ->  2      "noon" | "abba" | "d"
"abc"        ->  2      "a" | "b" | "c"
"racecar"    ->  0
```

## Step 1: Two sub-questions

1. For any `i, j`: is `s[i..j]` a palindrome?
2. Given that, what is the minimum number of cuts for each prefix?

## Step 2: Prefix DP

`cuts[j]` = minimum cuts for the prefix `s[0..j]`.

- If `s[0..j]` is itself a palindrome: `cuts[j] = 0`.
- Otherwise, the last piece is some palindrome `s[i..j]` with `i > 0`: `cuts[j] = min over such i of cuts[i - 1] + 1`.

Answer: `cuts[n - 1]`.

## Step 3: Checking palindromes efficiently

Checking each `s[i..j]` from scratch is O(n), which makes the whole thing O(n^3).

**Option A: palindrome table.** `P[i][j] = s[i] == s[j] and P[i+1][j-1]`, filled by increasing length. O(n^2) time and **O(n^2) space**.

**Option B (this code): expand around centers and update cuts on the fly.** Every palindrome is found by expanding from its center (see Longest Palindromic Substring, medium 67). Each time an expansion confirms that `s[lo..hi]` is a palindrome, relax `cuts[hi]` with `cuts[lo - 1] + 1` (or 0 if `lo == 0`). No table needed: **O(n) space**.

**Why is `cuts[lo - 1]` already final when it is read?** Every palindrome that ends at index `lo - 1` has its center at or before `lo - 1`, which is strictly before the current center. Centers are processed left to right, so all of them were already applied.

## Step 4: The code

Full source: [`palindrome_partitioning_min_cuts.dart`](palindrome_partitioning_min_cuts.dart) (run it with `dart run`).

```dart
// Palindrome Partitioning Min Cuts: fewest cuts so every piece is a palindrome.
// Expand around centers to mark palindromes while computing cuts[end] in one O(n^2) pass.
// O(n^2) time, O(n) space.

int palindromePartitioningMinCuts(String string) {
  final n = string.length;
  if (n == 0) return 0;
  // cuts[i] = min cuts for the prefix string[0..i] (inclusive). Worst case: i cuts.
  final cuts = List<int>.generate(n, (i) => i);
  void expand(int lo, int hi) {
    while (lo >= 0 && hi < n && string[lo] == string[hi]) {
      // string[lo..hi] is a palindrome: the prefix ending at hi can end with this piece.
      final candidate = lo == 0 ? 0 : cuts[lo - 1] + 1;
      if (candidate < cuts[hi]) cuts[hi] = candidate;
      lo--;
      hi++;
    }
  }

  for (var center = 0; center < n; center++) {
    expand(center, center); // odd length
    expand(center, center + 1); // even length
  }
  return cuts[n - 1];
}
```

### Walkthrough

- `cuts` starts with the worst case: prefix `0..i` cut into single characters needs `i` cuts.
- `expand(lo, hi)` grows the palindrome and relaxes `cuts[hi]` for every palindrome it confirms.
- The loop over centers calls both the odd and the even expansion.

## Step 5: Final cuts array for "noonabbad" (generated by running the algorithm)

| index | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|---|
| char | n | o | o | n | a | b | b | a | d |
| cuts | 0 | 1 | 1 | 0 | 1 | 2 | 2 | 1 | **2** |

- `cuts[3] = 0`: "noon" is a palindrome.
- `cuts[7] = 1`: "noon" + "abba".
- `cuts[8] = 2`: "noon" + "abba" + "d".

## Complexity

| Approach | Time | Space |
|---|---|---|
| Palindrome table + prefix DP | O(n^2) | O(n^2) |
| Center expansion + prefix DP | O(n^2) | O(n) |

## Common mistakes

- Returning the number of pieces instead of cuts (pieces - 1).
- Checking palindromes from scratch inside the DP (O(n^3)).

## What to remember

Precompute or discover palindromes efficiently (centers), and combine them with a prefix DP: `cuts[j] = min(cuts[i-1] + 1)` over palindromes ending at j.
