# Optimal Assembly Line

**Difficulty:** Very Hard | **Category:** Searching | **Pattern:** Binary search on the answer + greedy feasibility check

## The problem

An assembly line has steps that must be done in order, each with a duration. You must group the steps into **at most `numStations`** contiguous groups (stations). A station's time is the sum of its steps' durations, and the line runs at the speed of its **slowest** station. Return the **minimum possible time of the slowest station**.

```
steps = [15, 15, 30, 30, 45], numStations = 3  ->  60
```

Why 60: 45 cannot share a station with the neighboring 30 (75), so it sits alone. The remaining `[15, 15, 30, 30]` must fit in two stations; both splits `[15, 15, 30] [30]` and `[15, 15] [30, 30]` peak at 60.

## Step 1: DP (works, but slow)

`best[i][s]` = the minimum possible slowest-station time for the first `i` steps using `s` stations: try every position for the last station's start. O(n^2 * s) time.

## Step 2: Flip the question

Instead of "what is the best time?", ask: **"given a time limit T, can the steps be grouped into at most `numStations` stations, each taking at most T?"**

That question is easy to answer **greedily**: fill the current station with steps as long as the total stays within T; when the next step would exceed T, open a new station. Count the stations.

Why is greedy optimal for this check? Packing as many steps as possible into each station never hurts later stations: it only leaves fewer steps for them.

## Step 3: The answer is monotonic, so binary search it

If time T is feasible, every larger time is also feasible. So the feasible times form a range `[answer, infinity)`, and we can **binary search the smallest feasible T**.

Bounds:

- low: `max(steps)`: a station must at least fit its largest single step;
- high: `sum(steps)`: one station doing everything.

## Step 4: The code

```dart
// Optimal Assembly Line: split stepDurations into numStations contiguous groups minimizing the
// maximum group sum. Binary search on the answer with a greedy feasibility check.
// O(n log S) time (S = sum of durations), O(1) space.

int optimalAssemblyLine(List<int> stepDurations, int numStations) {
  var lo = stepDurations.reduce((a, b) => a > b ? a : b); // a station must fit the biggest step
  var hi = stepDurations.reduce((a, b) => a + b); // one station does everything

  bool feasible(int maxTime) {
    var stations = 1, current = 0;
    for (final d in stepDurations) {
      if (current + d > maxTime) {
        stations++;
        current = 0;
      }
      current += d;
    }
    return stations <= numStations;
  }

  while (lo < hi) {
    final mid = lo + (hi - lo) ~/ 2;
    if (feasible(mid)) {
      hi = mid; // mid works; try smaller
    } else {
      lo = mid + 1;
    }
  }
  return lo;
}
```

### Walkthrough

- `lo` and `hi` are the bounds from Step 3.
- `feasible(maxTime)` is the greedy check from Step 2.
- The loop is a lower-bound binary search: if `mid` works, the answer is `mid` or smaller (`hi = mid`); otherwise it is larger (`lo = mid + 1`).

## Complexity

- **Time: O(n log S)**, where S is the sum of the durations (each check is O(n); the binary search takes log S steps).
- **Space: O(1)**.

## Common mistakes

- Low bound of 0 or 1 (a station cannot be faster than its largest step; the check would still work but wastes iterations).
- Using `<` instead of `<=` in the feasibility count.

## The "binary search on the answer" family

The pattern: the answer is a number, and "is value X good enough?" is easy to check and monotonic.

- Split Array Largest Sum (LeetCode #410): identical.
- Capacity To Ship Packages Within D Days (#1011).
- Koko Eating Bananas (#875).
- Minimize the maximum distance to a gas station (#774, on real numbers).

FAANG interviewers love this pattern because it combines a monotonic predicate with a greedy check.

## What to remember

When "minimize the maximum" has a monotonic yes/no check, binary search the answer and verify each candidate greedily.
