# Right Smaller Than

**Difficulty:** Very Hard | **Category:** Binary Search Trees | **Pattern:** Merge sort counting (or an augmented BST)

## The problem

Given an array of integers, return an array where `output[i]` is the number of elements **to the right of index i** that are **strictly smaller** than `array[i]`.

```
[8, 5, 11, -1, 3, 4, 2]  ->  [5, 4, 4, 0, 1, 1, 0]
```

For 8: to its right, 5, -1, 3, 4, 2 are smaller: 5.

## Step 1: Brute force

For each index, scan everything to its right: **O(n^2)**.

## Step 2: AlgoExpert's intended approach: augmented BST

Process the array from **right to left**, inserting each value into a BST. Each node stores the size of its **left subtree**. While inserting value `v`, every time the path goes **right** past a node, that node and its entire left subtree are smaller than `v` and are to its right in the array: add `leftSize + 1` (or just `leftSize` if the node's value equals `v`). The sum at the end of the insertion is `output[i]`.

Average **O(n log n)**, but a plain BST degrades on sorted input to **O(n^2)**. Mention this weakness.

## Step 3: Guaranteed O(n log n): merge sort on indices

Sort the **indices** by value with merge sort, and count during the merges.

When merging a left half and a right half:

- every element in the right half was originally **to the right of** every element in the left half;
- when a left element is placed, the right elements already placed (say `j` of them) are **smaller** than it (they were placed first).

So each placed left element gets `+j`. Summed over all merge levels, every "smaller element to the right" pair is counted exactly once: at the level where the two elements are first separated into different halves.

Use `<=` when comparing, so equal values from the left are placed first and **not** counted (the problem wants strictly smaller).

## Step 4: The code

Full source: [`right_smaller_than.dart`](right_smaller_than.dart) (run it with `dart run`).

```dart
// Right Smaller Than: for each index, how many elements to its right are strictly smaller.
// Merge sort on indices; while merging, every element taken from the right half before a left
// element is smaller and to its right. O(n log n) time, O(n) space.

List<int> rightSmallerThan(List<int> array) {
  final counts = List<int>.filled(array.length, 0);

  List<int> sort(List<int> ids) {
    if (ids.length <= 1) return ids;
    final mid = ids.length ~/ 2;
    final left = sort(ids.sublist(0, mid)), right = sort(ids.sublist(mid));
    final out = <int>[];
    var i = 0, j = 0;
    while (i < left.length || j < right.length) {
      if (j == right.length || (i < left.length && array[left[i]] <= array[right[j]])) {
        counts[left[i]] += j; // right[0..j) are smaller than left[i] and positioned after it
        out.add(left[i++]);
      } else {
        out.add(right[j++]);
      }
    }
    return out;
  }

  sort(List<int>.generate(array.length, (i) => i));
  return counts;
}
```

### Walkthrough

- `counts` accumulates the answer per original index.
- `sort(ids)` merge-sorts a list of indices by `array[index]`.
- In the merge, `counts[left[i]] += j` adds the number of right-half elements already placed.
- The top-level call sorts all indices; only the side effect on `counts` matters.

## Step 5: Dry run on a small example `[5, 2, 6, 1]` (expected `[2, 1, 1, 0]`)

Every count contribution, generated by running the algorithm:

| merge | left half values | right half values | placed element | right elements already placed | contribution |
|---|---|---|---|---|---|
| 1 | [5] | [2] | 5 (index 0) | 1 (the 2) | +1 to index 0 |
| 2 | [6] | [1] | 6 (index 2) | 1 (the 1) | +1 to index 2 |
| 3 | [2, 5] | [1, 6] | 2 (index 1) | 1 (the 1) | +1 to index 1 |
| 3 | [2, 5] | [1, 6] | 5 (index 0) | 1 (the 1) | +1 to index 0 |

Totals: index 0: 2, index 1: 1, index 2: 1, index 3: 0. Result `[2, 1, 1, 0]`.

## Complexity

| Approach | Time | Space |
|---|---|---|
| Brute force | O(n^2) | O(n) |
| Augmented BST | O(n log n) average, O(n^2) worst | O(n) |
| Merge sort counting | O(n log n) | O(n) |
| Fenwick tree over compressed values (right to left) | O(n log n) | O(n) |

## Common mistakes

- Sorting values instead of indices (you lose where each count belongs).
- Using `<` in the merge comparison (counts equal values as smaller).

## What to remember

Merge sort separates every pair of elements exactly once; counting during the merge ("how many right elements came first") counts pairs with an order relationship in O(n log n).
